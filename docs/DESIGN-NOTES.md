# 設計審閱筆記：原企劃（Gemini 生成提示詞）的問題與處理方式

企劃整體方向很完整，但逐條實作時發現一些**互相矛盾、技術上不可行、或劇情邏輯有缺口**的地方。
下面列出每一點、我採取的處理，以及仍需要你決定的開放問題。所有文字都集中在 `src/data/script.js`，
標記【補充文案】的都可以直接改。

---

## A. 規格之間的矛盾

### A1.「嚴禁畫面閃爍」 vs 「車燈一閃而過」「濃煙瞬間湧入」「雪花雜訊」
「一閃而過的刺眼車燈」與「瞬間湧入」字面上就是突發的亮度/畫面劇變，正好是零跳臉與光敏感族群要避免的東西；
監視器的雪花雜訊本質上也是高頻閃爍。

**處理**：
- 車燈改為「掃過」：0.6 秒以上漸亮、約 1 秒以上漸暗，整段 2.5–3 秒，重點放在**牆上被拉長的影子**而不是強光本身。
- 濃煙用約 7 秒「翻湧著吞沒」房間，不是一瞬間。
- 雪花雜訊低對比、平均亮度固定；另外提供**光敏感模式**（標題/暫停畫面可切換），雜訊改為緩慢流動、關閉頭部擺動與色差。
- 全域規則：任何亮度變化 ≥ 0.4 秒；0.25 秒內整體亮度變化 ≤ 30%；不穩燈管只做緩慢、≤15% 的起伏。

### A2.「雕像般絕對靜止」 vs 第三幕「正拼命想撬開防爆門」
第一幕要求人影被看著時絕對靜止；第三幕高清畫面卻描述他在拼命破門。

**處理**：低畫質（第一幕）嚴格遵守盲區規則；**高清（第三幕）他會動**——緩慢、筋疲力竭地揮斧劈門，並在主控室裡聽到隔門的悶響。
「被看著就不動」被重新詮釋為主角妄想的一部分：恢復真實畫面的那一刻，他其實一直是個活生生、正在救人的人。
（若你偏好第三幕也靜止，在 `RevelationState` 把 `setHDAction(true)` 拿掉即可。）

### A3. 人影「推進」與對講機時間軸會不同步
若玩家整段第一幕都盯著 CAM-03，人影永遠不會動；但 02:13 對講機卻說「我要破門了」——畫面與聲音會穿幫。
反過來，若玩家一直移開視線，人影可能 02:02 就到門口了。

**處理**：時鐘採「節拍閘門」：每一個劇情事件（02:03 / 02:05 / 02:08 / 02:13）時鐘會停住直到玩家完成它；
每個節拍設定人影推進的**上下限**。對講機刻意放在**防爆門旁的西牆**（門鈴的位置，也正是門外那個人的聲音來源），
接聽時一定要轉身背對監視器 → 人影一定會在玩家不看時補上進度。另外規定：人影只有在「先被你看見、你再移開視線」之後才推進，
所以每一次推進玩家都會察覺到。

### A4. 「Frustum Culling」字面上不足以判定「玩家正在看」
Three.js 的 frustum culling 是渲染最佳化；而且監視器攝影機本身永遠「看得到」人影，真正重要的是**玩家有沒有在看那台 CRT**。
單純的視錐相交太寬鬆（螢幕在畫面邊角也算）。

**處理**：`GazeSystem` 同時要求：視錐相交（`Frustum.intersectsBox`）＋視線中央 34° 錐＋距離＋射線遮蔽（被門牆擋住不算）
＋螢幕正面朝向＋沒有在檢視物品＋沒有切到別的頻道。

## B. 劇情/空間邏輯缺口

### B1. 兩條「維修廊道」會撞在一起
CAM-03 拍的是「公務維修廊道 B區」，第三幕又說 CAM-03 在「防爆門外」；第二幕玩家要「進入地下公務維修廊道」。
如果是同一條廊道，玩家第二幕就會跟人影正面相遇（而且會變成貼臉驚嚇）。

**處理**：拆成兩條——
- **西牆防爆門 → B 區廊道**（CAM-03 拍攝處，人影/消防員所在，玩家永遠進不去）。
- **東牆側門 → 地下公務維修廊道**（第二幕路線，通往電閘室）。

### B2. 02:03 他說「門……打不開」，但畫面上他還在廊道遠端
日誌寫「02:05 有人在敲防爆門」，對講機 02:03 他已經在說門打不開，可是 CAM-03 前期畫面裡他還在很遠的地方。
**詮釋**：低畫質畫面裡「逐漸逼近」本身就是主角的扭曲知覺；高清畫面揭露他**其實一直就在門口**。這反而強化了反轉，
所以保留原文、不做修改。

### B3. 真相揭露的文本不夠
企劃說第三幕「對講機傳來清晰錄音，揭露三年前的真相：……鎖死防爆門並切斷通風……」，
但階段四錄音的實際台詞只有求救，**沒有**說出「鎖門」「切斷通風」「兩人都死了」這些事實。

**處理（【補充文案】）**：
- 右側機電螢幕在高清後顯示「通風：主排風 手動切斷（02:11 操作員）」——第一幕玩家「重啟通風」的動作，被揭露其實是切斷。
- 左側螢幕顯示「事故調查摘要（三年前）」：救援隊員於防爆門外殉職、值班員於室內窒息、防爆門由內部反鎖。

### B4.「寫下最後一句話」沒有指明是哪一句
**處理**：解讀為便利貼的最後一句「**鎖死防爆門。**」——便利貼是主角寫給下一輪自己的訊息（呼應日誌「字跡一模一樣」），
終幕畫面中便利貼已寫好大半，筆寫下最後一句。循環每多一次，便利貼角落多一道「正」字記號。

### B5.「每次玩家從廊道返回主控室」——正常流程只會返回一次
**處理**：復電前每次折返主控室都會累加一次腐化（最多 0.45）；復電後回來直接跳到明顯陳舊（≥0.6），聽完錄音再到 0.85，終幕焦黑。

## C. 技術限制

| 問題 | 處理 |
|---|---|
| 「模組化」與「貼上即可執行」衝突：ES modules 無法從 `file://` 載入，CDN 又算外部依賴 | 原始碼模組化（`src/`），以 esbuild 打包成**單一自足 HTML**（three.js 內嵌、零外部請求），雙擊即可玩 |
| 瀏覽器自動播放政策：Web Audio 必須由使用者點擊啟動 | 標題畫面「點擊開始交接」，同一次點擊啟動音訊與指標鎖定 |
| Pointer Lock 在部分 iframe/瀏覽器不可用 | 自動退回「按住左鍵拖曳環顧」模式（Esc 一樣可以暫停） |
| 企劃指定 `PointerLockControls` | 用的是同一套瀏覽器 Pointer Lock API，但改由自製 `PlayerController` 管理視角：甦醒起身、轉頭看門、坐下/趴倒這些**劇本運鏡**需要獨立的 yaw/pitch/roll 狀態與補間，`PointerLockControls` 會直接改寫相機旋轉而且沒有拖曳退回模式。手感（滑鼠靈敏度、俯仰上限）等同 |
| Web Audio 無法程式化合成**聽得懂的中文語音** | 對講機用共振峰濾波噪音合成「像人聲的呢喃」＋喘息/敲擊/咳嗽/斧頭聲，配逐段累加的字幕；字幕最終字串與原文逐字相同。之後若有錄音可直接替換 |
| 不能載入網路字型 | Canvas 與 UI 用系統字型堆疊；便利貼/日誌手寫字優先用系統楷體（標楷體/楷體），沒有時退回一般字型並加逐字抖動模擬手寫 |
| 「降低環境光源色溫」 | 依字面實作：色溫降低＝由冷白日光燈 (≈6500K) 變成髒琥珀色 (≈3000K)，同時也預示火災。若你原意是「變冷/變藍」，改 `ControlRoom` 的目標色即可 |

## D. 需要你決定的開放問題

1. **錶的主人是誰？** 「給阿哲，值夜班注意安全」——「值夜班」指向值班員（主角＝阿哲），但錶卻在主角從未去過的維修廊道排水溝旁。
   - 若要明確是**主角的**：把錶移到主控室（例如椅子下）。
   - 若要明確是**消防員的**：把「值夜班」改成「出勤」。
   - 目前保留原文的曖昧（兩種讀法都成立：救援者的錶停在 02:14:08，恰是跳電/濃煙倒灌的那一刻）。
2. **電閘室的雨衣屬於誰？** 高清畫面中消防員身上穿著外套，那鐵架上這件是誰的？目前視為同隊隊員/記憶碎片，不影響劇情；
   若想更緊密，可以讓高清畫面中的消防員**沒穿外套**（把外套留在電閘室是為了鑽進狹窄的廊道）。
3. **工作人員名單** 目前是佔位文字（「企劃・劇本・文案：原始企劃案」），請換成實際名單。
