# 《盲區交接》v3 實作計畫

> 依據：`docs/script/script-v3-draft.md`（owner 已同意方向）。
> 狀態：計畫，尚未動程式。

## 0. 已定案的前提

採用 v3 草案第 6 節的建議值。owner 若有異議，開工前提出即可。

| 問題 | 定案 |
|---|---|
| 對講機＝三年前的錄音 | 採用。玩家的回應不改變志遠的台詞，只有「開門」改變結局 |
| CAM-00 | 採用。只在 02:12 與結局 A 出現，控制台不加按鈕 |
| 結局 B／C 之後能否再次交接 | 結尾選單只留「工作人員名單」。標題畫面仍可「重新開始」（從頭玩，非循環） |
| 主角配音 | 不配音，只有字幕；唯一例外是 02:13 對講機裡的耳語「不要開。」 |

**工作方式**
- 每個階段都在獨立分支開發，完成後才合併。
- 每完成一項就提交，每 40 分鐘推一次 GitHub，防止用量上限中斷時丟失進度。
- 每個階段結束都會做三件事：自動測試、審查、修正，然後更新 GitHub Pages，交給 owner 試玩。
- 線上版本在每個階段驗證通過前保持不變。

## 階段 1：劇本與選擇系統（核心，最優先）

**目標**：三條路線、三個結局都走得通，先用簡單畫面撐住。

| 項目 | 內容 |
|---|---|
| 1.1 文案 | `script.js` 換成 v3 全文，包含對講機分支、抽屜、濕腳印、CAM-00 標籤、結局字卡 |
| 1.2 對講機選擇介面 | 接聽中出現 2–3 個短句。電腦用數字鍵或點擊，手機用大按鈕。第 2 通在選項出現時，對方已經開口 |
| 1.3 回應邏輯 | 對講機 1 依選擇播「重複你的話」或「我聽得到你在呼吸」；對講機 2 依選擇播「你每次都這樣說」或「快開門」；對講機 3 疊上第二個聲音 |
| 1.4 開門時間窗 | 02:05 敲門後，以及 02:13 到跳電之間，手輪可以「解除氣壓閥」 |
| 1.5 通風面板 | 改成誠實標示「切斷主排風（防止煙霧回灌主控室）」 |
| 1.6 結局狀態 | 新增結局 B、C 的狀態骨架：先用淡出加字卡，場景在階段 3 補完；結尾選單依結局改變 |
| 1.7 字幕 | 說話者分成「對講機」和「阿哲」 |

**驗收**
- 自動駕駛分別跑完 A、B、C 三條路線，沒有卡關、沒有錯誤。
- 選擇介面在電腦和手機的直向、橫向都能操作。
- owner 試玩一次。

**規模**：中。

## 階段 2：恐怖場面（讓它「恐怖」）

| 項目 | 內容 |
|---|---|
| 2.1 抽屜 | 控制台新增可開的抽屜，裡面塞滿便利貼；檢視時特寫最底下那張被塗掉的 |
| 2.2 濕腳印 | 02:10 起，只在玩家背對門口時出現（沿用盲區判定）：從門口到椅子後面的靴印 |
| 2.3 門縫滲煙 | 02:05 敲門後，門底下有低矮的薄煙（沿用現有煙霧系統，只是小量） |
| 2.4 CAM-03 空手 | 對講機 2 期間，人影是面牆、雙手下垂的姿勢 |
| 2.5 CAM-00 | 第五個監視器場景：從天花板拍的主控室縮小版，有人趴在控制台。<br>流程：02:12 自動切入 → 移開視線再看回來時標籤改變 → 約 15 秒後切回 CAM-03 |
| 2.6 結局 A 收尾 | 寫完便利貼後放進抽屜；趴倒後鏡頭升到 CAM-00 角度，轉成低畫質黑白並浮現標籤 |

**驗收**
- 每個場面都要截圖檢查：手機上看得清、不會突然跳出、亮度變化符合光敏規則。
- CAM-00 只在需要時渲染，不能拖累手機效能。

**規模**：中到大。

## 階段 3：結局 B、C 的完整場景

| 項目 | 內容 |
|---|---|
| 3.1 結局 B「02:15」 | 開門後，門外靠著門框坐著的消防員（沿用高清 CAM-03 模型：無外套、面罩熔化、斧頭在腳邊、手握錶）。主角坐下、時鐘走到 02:15、字卡 |
| 3.2 結局 C「回頭」 | 開門後站著的消防員（有雨衣、頭燈），說「阿哲。走。」。玩家跟著他走進 B 區廊道，這是第一人稱、彩色版本，結構沿用 CAM-03 的廊道 |
| 3.3 回頭判定 | 回頭時看見煙霧中的主控室和趴著的自己；他停下來等你；字卡依「有沒有回頭」改變 |
| 3.4 出口 | 廊道盡頭漸亮成清晨的隧道出口，淡出 |

**驗收**
- 兩個結局都從開門一路走到字卡，畫面截圖逐格檢查。
- 光敏規則：開門、晨光漸亮都要緩慢。
- 手機可操作：結局 C 要用搖桿走路。

**規模**：大。

## 階段 4：真實音效與人聲（可與階段 2、3 並行）

### 4.1 音效
- 在這個環境安裝 earshot，產出第一批音效樣本：
  - 腳步：地磚、水泥、水漬
  - 門與機構：敲鐵門、氣壓閥、拉桿、抽屜、便利貼紙聲
  - 人體：心跳、喘息、咳嗽
  - 火：火焰、遠方轟隆
  - 底噪：房間、隧道風
- earshot 沒有的，從 Freesound 或 BigSoundBank 找 CC0 錄音，例如：
  - 日光燈嗡鳴
  - 通風風扇
  - CRT 高頻聲
  - 無線電雜訊
  - 斧頭劈鐵門
  - 消防警報
- 每個音效記錄來源與授權，寫進 `docs/AUDIO-CREDITS.md`。

### 4.2 人聲（需要 owner 決定來源）
- 志遠約 12 句，加上阿哲的耳語 1 句。台詞清單在階段 1 定稿後產出。
- 來源有兩個選項：
  - **建議**：owner 或朋友用手機錄音，我處理成對講機的無線電音質。
  - 開源中文語音合成。
- 錄音要求：安靜房間、手機貼近嘴巴約 20 公分、每句錄 2–3 次。

### 4.3 整合
- 音檔轉成 Opus/OGG，放在 `audio/` 資料夾，預估 3–6 MB，遊戲開始時預先載入。
- 音檔載入失敗，或直接用本機雙擊開檔時，自動退回現有的合成音效。
- 用 3D 空間定位，讓聲音真的來自左後方的門、頭頂的風管、背後的椅子。
- 音量規則照舊：峰值 ≤ -10 dBFS，沒有突發巨響。

### 4.4 試聽回合
- 我先產出一個「音效試聽頁」，用 Artifact 呈現，可以逐一播放、標記喜不喜歡。
- owner 戴耳機聽過、點頭後，才整合進遊戲。

**驗收**：owner 試聽通過；整場最大音量量測合格；手機上能正常播放（包括 iPhone）。

**規模**：中（不含錄音時間）。

## 階段 5：收尾

- **重新量測三條路線的時長**：目標 A 約 10–13 分、B 約 6–7 分、C 約 4–5 分。
- **精簡**：減少第二、三幕的走路與閱讀；調整節奏參數。
- **全面審查**：電腦節奏體驗、手機觸控、程式迴歸、光敏與音量。
- **更新文件**：ARCHITECTURE、DESIGN-NOTES、README，以及新的 AUDIO-CREDITS。
- **部署**：發布到 GitHub Pages，更新 Artifact。

## 順序與依賴

```
階段 1 劇本＋選擇 ──┬──→ 階段 2 恐怖場面 ──→ 階段 3 結局場景 ──→ 階段 5 收尾＋部署
                   └──→ 階段 4 音效＋人聲（4.1 可立即開始；4.2 等台詞定稿）──┘
```

- 每個階段結束都可以獨立上線試玩。
- 建議試玩點：
  - 階段 1 後：試三條路線與選擇手感。
  - 階段 2 後：試恐怖程度。
  - 階段 4.4：試聽音效。
  - 階段 5：最終版。

## 需要 owner 提供

1. 人聲來源：自己錄，還是語音合成？
2. 各階段結束時的試玩回饋。
3. 音效試聽頁的選擇。
4. 工作人員名單的實際名字，目前仍是佔位文字。

## 風險

- **用量上限**：分階段、頻繁提交，可降低中斷損失。
- **手機效能**：CAM-00、結局 C 的廊道都是新場景，只在需要時建立或渲染。
- **檔案變大**：從單一 HTML（約 1.4 MB）變成 HTML 加音效資料夾（約 5–8 MB）。Pages 沒問題，第一次載入會久幾秒。
- **人聲品質**：這是代入感的關鍵，錄音品質直接決定效果。
